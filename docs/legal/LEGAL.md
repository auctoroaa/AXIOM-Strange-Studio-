All public descriptions must distinguish:
- **Implemented:** code exists in the repository.
- **Tested:** a specified test was actually executed and its result recorded.
- **Verified:** the stated acceptance criteria passed with reproducible evidence.
- **Proposed:** design intent without a complete implementation.
- **Unverified:** present, but not yet supported by sufficient verification.

A workflow, schema, API route, UI element, Architecture Pack, or CI configuration
must not be described as production-ready merely because files exist. Do not
claim autonomous intelligence, correctness, security, persistence, scalability,
real-time observability, reversibility, or interoperability beyond what tests
and runtime evidence demonstrate.

Current known boundary: the API uses process-local memory and is not durable
storage. Do not claim production-grade authentication, authorization, tenancy,
or deployment security unless these are implemented and independently tested.
